# Contributing to Awesome Open Source Universe

Thanks for helping make this the best open source directory on the internet! 🚀

## What qualifies

| ✅ Accepted | ❌ Not accepted |
|------------|----------------|
| Open source with a clear OSI-approved license | Closed source / proprietary / "source available" tools |
| Active: commits within the last 12 months | Abandoned (2+ years no activity) |
| Solves a real developer or user problem | Pure clones with no added value |
| Public GitHub/GitLab repository | No source code available |
| Has a README that explains what it does | Empty, placeholder or spam repos |

## How to add a project

1. **Fork** the repo and create a branch: `add-<project-name>`.
2. Find the right category in [`README.md`](README.md). If none fits, propose one in an issue first.
3. Add **one row** in the category table, **in alphabetical order**:

   ```markdown
   | [**Project**](https://github.com/owner/repo) | One-line description (max ~100 chars, no marketing fluff) | [![Stars](https://img.shields.io/github/stars/owner/repo?style=flat-square&color=f4c542)](https://github.com/owner/repo) |
   ```
4. Make sure the link works and the project isn't already listed (search the README).
5. Open a PR titled `Add <Project> to <Category>`. One project per PR keeps review fast.

## Description style

- Start with a capital letter, no emojis.
- Say **what it does** and what makes it different (e.g. "self-hosted", "privacy-focused").
- Avoid words like "best", "awesome", "revolutionary".

## Other ways to help

- 🐛 Report dead or outdated links via an [issue](../../issues/new/choose).
- 🗑️ Suggest removal of abandoned projects.
- ✏️ Fix typos, improve descriptions, or improve categorisation.
- ⭐ Star and share the list.

## Pull request checklist

- [ ] Project is open source with a license
- [ ] Repo has had activity in the last 12 months
- [ ] Added to the correct category, alphabetically
- [ ] Link works, description is concise and neutral
- [ ] Not a duplicate
- [ ] One project per PR
